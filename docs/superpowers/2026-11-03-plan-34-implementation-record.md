## Task 1 — contracts

Public evidence only, no tenant observation: the Management API OpenAPI
(downloaded 2026-11-03), Auth0's published docs corpus (`llms-full.txt`,
fetched 2026-11-03; each route, rule and limit names its page URL in
`internal/phonerules/inventory.json`), the MIT auth0.js passwordless module
(`/passwordless/verify_redirect` parameters) and the pinned
`@auth0/auth0-auth-js` 1.16.1 package (start and OTP grant request shapes).
The inventory was generated by a scratch script from the OpenAPI plus
hand-frozen rulings; the script is not part of the repository.

- `internal/phonerules`: `Route` (37 routes across spec §3–§7 and §10),
  `ConnectionOptions`, `TemplateTypes`, `ProviderNames`, `ProviderSchemas`,
  `Routing`, `Screens`, `ActionTrigger`, `MaskPhone`, `Limits`, plus log-code
  emission rules, tenant-setting semantics, gateway and backoff rules and
  gaps P1–P24. As in Plan 33, the type is `RouteSchema` because Go cannot
  declare a type and function both named `Route`.
- Auth0's own path is used for the protection routes:
  `/api/v2/attack-protection/phone-provider-protection` (the name in the
  brief matched Auth0).
- API documents: 15 Management operations (branding phone providers and
  templates, phone-provider-protection), `email`/`sms` connection strategies
  and their option schemas, the `ActionTrigger` enum, three Authentication API
  operations (`POST /passwordless/start`, `GET`/`POST
  /passwordless/verify_redirect`), the passwordless OTP grant
  (`x-passwordless-grants`) and `phone_number` on signup. Every operation has
  `x-source`.
- The generated Authentication API interface required three adapters
  (`internal/server/passwordless_bridge.go`); they answer 501
  `passwordless_unavailable` until Task 10. Management routes fall to the
  generated `Unimplemented` (501) until their tasks.
- `internal/actionsrules`: `custom-phone-provider` (v1, one binding, enforced
  in `ValidateBindings`) and `send-phone-message` (v2, blocking) moved from
  deferred to supported. Tests that used `send-phone-message` as an
  unsupported trigger now use `custom-token-exchange`; the trigger list tests
  expect the two new triggers; the per-trigger dry-run in `internal/mgmt`
  skips the phone triggers until the runner learns their handlers (Task 9).
- `internal/logrules`: the twelve Plan 34 codes keep `plan: 34`, now
  `status: deferred` with a note pointing at the frozen emission rules.
- Docs: D-0060 (documented values, LR 1–6, interface ruling, P1–P24),
  matrix, roadmap status line, Plan 34 follow-ups. Console types were not
  regenerated (no console toolchain installed); the console task does it.
