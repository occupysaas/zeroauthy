## D1 inventory summary

- Registry is the `auth0ApiHandlers` object in the pinned `lib/tools/auth0/handlers/index.js`; it registers 49 handler keys, including `clientAuthCredentialsPre` as a deploy-only pre-pass. Task 1's manifest inventories every registry key. The public `AUTH0_EXCLUDED` config filters `handler.type`, so Task 9 validates exact type names from installed 9.1.0 before running.
- The pinned tool has YAML and directory serializers under `lib/context/yaml` and `lib/context/directory`. Directory exports split resource families into files/directories and support file references; YAML stores resource collections in one tenant document and supports references. Synthetic fixtures exercise both formats through the parser/comparator; the CLI lane below uses the unmodified installed CLI.
- Existing observations establish: clients match by `client_id`, then name; client secrets and read-only runtime/system fields are omitted; database connections match by name then ID and enabled clients are applied through a dedicated endpoint; resource servers match by ID then identifier and the Management API is excluded by its name; grants use ID then client/audience/subject identity, with the tool's own and system grants excluded. See `management-clients.md`, `management-apis.md` and `management-connections.md` for sanitized details.
- Exported client credentials are not available in ordinary tool exports. Preserving IDs/secrets therefore uses the separate protected create-only bootstrap; generated-ID mode uses explicit reference mapping. Export equality alone does not prove behavior for fields stored but not enforced.
- The nonempty local CLI families are `clients`, `resourceServers`, `clientGrants` and `tenant`. The manifest marks `databases`, `connections` and `attackProtection` explicitly tool-unsupported: the first requires the absent Actions API, the second filters out the currently supported database strategy, and the third requires phone-provider protection. Synthetic database/connection parser/reference fixtures remain covered; their tool migration is unavailable, not passing.
- The actual local CLI lane passes all four combinations of YAML/directory and generated/preserved credentials. Each run uses a fresh database, validates the installed registry, disables deletion, excludes the exact source/target tool-client names using `AUTH0_EXCLUDED_CLIENTS`, checks import/repeat/update comparisons and verifies runtime client-credentials issuance. The source API collision preflight and deliberately changed field comparison fail as expected. Target-only application survival is inventoried separately rather than hidden by comparison. No raw export or secret enters a result report.
- Preserved mode uses a second identifier-bearing export (`AUTH0_EXPORT_IDENTIFIERS=true`) solely for offline bootstrap. Ordinary import uses the default name/reference export so read-only source IDs are not passed to public create endpoints. The protected secret file is supplied separately. Bootstrap reruns reject expired secrets and changed authentication/tenant identities.
- Directory exports store client grants in `grants/`; the shared loader maps that directory to the `clientGrants` family. Earlier empty-family and extra-tool-client failures are resolved. Upstream export remains unavailable without a separate authorized observer; local pass does not substitute for that evidence.

## D2 retired-resource boundary

Pinned handler paths are `lib/tools/auth0/handlers/{rules,rulesConfigs,hooks}.js`; the adapters live under the corresponding YAML/directory handler paths. Only the documented collection read paths needed for export are in the Plan 20 shim inventory: `GET /api/v2/rules`, `GET /api/v2/rules-configs`, and `GET /api/v2/hooks`. Public references document Rules and Hooks as arrays, with optional totals for the paged collections; rules-config keys are a collection. The implementation returns empty collections and never executes scripts. The local scope mapping is `read:rules` for rules and rules-configs and `read:hooks` for hooks, following the documented Rules/Hook scope families; rules-config scope was not independently established. Writes are rejected and no wildcard fallback is used. Exact tenant-specific errors remain a local contract because no observer report was supplied.
